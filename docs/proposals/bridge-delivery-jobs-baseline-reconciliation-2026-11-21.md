## Finding

The active migration `20261114135437_bridge_delivery_job_ownership_20261114.sql` alters `public.bridge_delivery_jobs` and adds `requested_by` / `request_note`, but does not create the table.

The Production schema has historically contained this table as a **pre-ledger baseline**. The active 69/70-row recovered SQL migration ledger does not contain its original CREATE TABLE statement. The local migration replay script reconstructs an empty baseline immediately before replaying the ownership migration. Testing has no `bridge_delivery_jobs` relation, so application reads against that project fail until the baseline is included in an isolated replay.

The existing replay fixture records the following baseline contract:
- UUID primary key, generated by `gen_random_uuid()`
- `title_id text` referencing `bridge_titles(id)`
- job types: `dubbing`, `loudness`, `imf`, `dcp`, `human_qc`, `localization`
- states: `requested`, `in_progress`, `completed`, `failed`, `approved`
- assignment, receipt URL, admin sign-off, timestamps
- RLS enabled and an authenticated internal-only policy using `private.bridge_is_internal()`

## Migration-history constraint

Do **not** rewrite the already-recorded ownership migration to add the table: changing an applied migration is not a safe forward-only repair. Do not add an earlier timestamped migration without first reconciling remote migration history; it may be out of order relative to the already-applied ownership migration.

The source currently keeps the pre-ledger baseline in `scripts/supabase-migration-replay.mjs`. That is an isolated replay fixture, not an authoritative versioned production migration. A separately approved migration-history reconciliation is required before promoting a canonical baseline migration into the active chain.

## Proposed baseline SQL (review only; not an active migration)

```sql
create table if not exists public.bridge_delivery_jobs (
  id uuid primary key default gen_random_uuid(),
  title_id text not null
    references public.bridge_titles(id) on delete cascade,
  job_type text not null
    check (job_type in ('dubbing','loudness','imf','dcp','human_qc','localization')),
  status text not null default 'requested'
    check (status in ('requested','in_progress','completed','failed','approved')),
  assigned_vendor text,
  delivery_receipt_url text,
  admin_sign_off boolean not null default false,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index if not exists bridge_delivery_jobs_status_idx
  on public.bridge_delivery_jobs(status);
create index if not exists bridge_delivery_jobs_title_id_idx
  on public.bridge_delivery_jobs(title_id);

alter table public.bridge_delivery_jobs enable row level security;
revoke all on table public.bridge_delivery_jobs from public;
grant all on table public.bridge_delivery_jobs to anon, authenticated, postgres, service_role;

do $$
begin
  if not exists (
    select 1 from pg_policy
    where polrelid = 'public.bridge_delivery_jobs'::regclass
      and polname = 'bridge_delivery_jobs_internal_only'
  ) then
    create policy bridge_delivery_jobs_internal_only
      on public.bridge_delivery_jobs
      for all to authenticated
      using ((select private.bridge_is_internal()))
      with check ((select private.bridge_is_internal()));
  end if;
end $$;
```

This SQL is deliberately **not** placed in `supabase/migrations` because its correct version position cannot be established without remote migration-history reconciliation. It is a proposal only.
