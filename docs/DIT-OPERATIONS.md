# Bridge DIT Operations — Preview / Testing DB only

This runbook describes the DIT code added in PR #499. It does not authorize Production use.

## Hard safety gate

The DIT write functions call `assertDitStagingDatabase()` before every database mutation. They require all of the following:

- `BRIDGE_DB_TARGET=STAGING`
- Database connection URL identifies Supabase project `jbymleftneggcgutlcqu`
- `SUPABASE_URL` identifies `https://jbymleftneggcgutlcqu.supabase.co`

If any check fails, ingest, replication, conversion queue updates, reviews and sign-off are blocked. Do not use Production DB project `mlmgugivsyoxzdgwkbpu`. Do not copy Production credentials into Preview.

Set these only after the Testing DB migration history, schema, RLS/grants and Preview Supabase target have been reconciled and separately approved:

- `OCI_TENANCY_OCID`, `OCI_USER_OCID`, `OCI_FINGERPRINT`, `OCI_PRIVATE_KEY`
- `OCI_REGION`, `OCI_BUCKET_NAME` for MASTER

- `OCI_BACKUP_2_REGION`, `OCI_BACKUP_2_BUCKET`

The server requires three distinct region/bucket pairs. Current OCI copy operations use one configured OCI tenancy and its credentials across the three regions. This provides regional/bucket separation, **not separate-tenancy/account isolation**; an account-level compromise remains a common-mode risk. Do not certify the copies as fully independent failure domains until separate-tenancy or equivalent independently administered storage targets are implemented and tested.

## Studio workstation worker

The worker is a local, no-paid-service FFmpeg/FFprobe process. Install FFmpeg and FFprobe on the authorized Studio workstation. Configure environment variables in the workstation shell only:

- `DIT_WORKER_BASE_URL`: authenticated Preview app base URL
- `DIT_WORKER_TOKEN`: same Preview-only secret as the API
- `DIT_WORKER_ID`: stable worker identifier
- `DIT_WORKER_ONCE=1` for one job; `0` to poll continuously
- Optional `FFMPEG_PATH` and `FFPROBE_PATH`

Run:

```sh
node scripts/dit-worker.mjs
```

The worker downloads a signed RAW object, recomputes SHA-256 against the verified Bridge manifest before transcoding, uses approved FFmpeg profiles, uploads output to MASTER and BACKUP_1, and submits evidence. The server reads both outputs back and checks byte size and SHA-256 before marking the conversion complete. Worker errors are persisted as retry/failed states; retries are bounded.

## Operational sequence

1. Admin/Studio selects a title and creates a production and shooting day.
2. Register physical camera card A/B/C and its card number.
3. Select the original camera file; verify metadata against the camera report.
4. Browser computes SHA-256 in 8 MiB chunks.
5. Server issues a short-lived OCI upload URL only after STAGING guard and role checks.
6. MASTER upload completes; server streams the object back and calculates SHA-256.
7. Server copies to BACKUP_1 and BACKUP_2 in distinct configured regions/buckets; it reads each full object back and checks exact byte size and SHA-256.
8. Any failed copy quarantines the card. No DIT sign-off is issued.
9. Approved conversion job is queued; the local FFmpeg worker processes it.
10. Admin/Super Admin performs the human clip review and card sign-off. Sign-off is derived from persisted manifest/copy evidence, not upload progress.

## Current scope and known gaps

- Current browser DIT workspace handles video originals. Audio and stills require their own media-asset ingest/review path before a full production package can be certified.
- Current replica configuration separates regions and buckets within one OCI tenancy; it is not separate-account isolation.
- Conversion output currently stores verified MASTER and BACKUP_1 copies; it does not yet create a third converted-output copy.
- Worker FFprobe metadata is generated by the trusted workstation worker; server verifies byte-for-byte read-back but does not run an independent FFprobe process.
- No Preview environment variables have been set and no actual object has been uploaded/copied by this change.
- Migration is not applied to STAGING or PRODUCTION. No Production deployment has occurred.
